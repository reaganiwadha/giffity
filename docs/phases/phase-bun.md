# Phase (out of order) — Bun single binary + install script

Pulled ahead of Phases 2–5 at the owner's request so distribution is solved
early. Node remains the primary dev/test runtime; Bun is a packaging target only.

## Done

- `bun run build-bun` (`scripts/build-bun.ts`) — runs `npm run build`, codegens
  the embedded-UI manifest, then `Bun.build({ compile })` a single
  `dist-bin/giffity(.exe)`. Bun-only scripts guard with
  `scripts/lib/require-bun.ts` (fail with a message if run under node).
- **UI embedding** — `scripts/gen-embedded-assets.ts` walks
  `packages/cli/dist/ui/client` and writes
  `packages/cli/src/generated/embedded-assets.ts` with
  `import … with { type: "file" }` entries (Bun embeds them). Normal Node builds
  use an empty stub (regenerated by `packages/cli/build.ts`); `build-bun`
  swaps the real file in for the compile and restores the stub after.
  `packages/cli/src/assets.ts` + `serveUi()` in `server.ts` prefer embedded
  assets, falling back to disk.
- **SQLite** — `better-sqlite3`'s native `bindings` lookup does not survive
  `--compile`, so `build-bun` aliases `better-sqlite3` →
  `packages/cli/src/sqlite-bun.ts`, a `bun:sqlite` subclass with a `.pragma()`
  polyfill. Node builds keep `better-sqlite3` untouched.
- **Version** — `require('../package.json')` (breaks in `--compile`) replaced by
  a generated `packages/cli/src/generated/version.ts` (written by
  `packages/cli/build.ts`).
- `doctor` no longer uses `createRequire`.
- `install.sh` / `install.ps1` — ensure bun, `npm install`, `bun run build-bun`,
  copy the binary to `~/.local/bin` / `%LOCALAPPDATA%\Programs\giffity`.

## Verified

- `npm run build` + `npm test` green (Node path unchanged).
- Compiled `dist-bin/giffity.exe` (~123 MB) in a scratch repo: `--version`,
  `doctor`, `agent comment`, and the HTTP server (embedded UI `/`, `/assets/*`,
  SPA fallback `/diff`, `/api/sessions`, `/api/threads`) all 200.
- Node `dist/index.js` still serves the UI from disk.

## Not done / follow-ups

- Cross-compilation (`--target=bun-linux-x64` etc.) for GitHub Releases.
- `giffity update` still assumes an npm global install.
- Binary is large (bundles the Bun runtime); acceptable for now.
